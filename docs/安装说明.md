# CCF QQ 频道提醒：安装说明

这是连接 OneBot v11 正向 WebSocket 的独立 Python 服务。安装时无需修改骰子脚本，也无需重启骰子程序。它不能作为海豹骰 JavaScript 扩展直接导入。

## 条件

- Python 3.10 或更高版本，支持 `venv`。
- 已登录的 NapCat 或兼容 OneBot v11 服务，启用正向 WebSocket。
- 可访问 CCFOLIA、Firebase Auth、Firestore 和 Python 依赖源的网络。
- CCFOLIA 邮箱密码账号，具备目标房间访问权限。
- 自动安装常驻服务需要 Linux 与 systemd 用户服务；无此环境时手动运行。

填写 OneBot 正向 WebSocket 的地址，例如 `ws://127.0.0.1:3001`。NapCat 管理页面和反向 WebSocket 地址不适用。同机运行可使用回环地址，无需新增公网监听端口。

## 校验并安装发行包

将发行包与 `SHA256SUMS` 放在同一目录。选择一种包格式，在自己的系统上核对对应 SHA-256 值：

```bash
sha256sum ccf-qq-relay-1.1.0.tar.gz
```

解压并进入发行目录：

```bash
tar -xzf ccf-qq-relay-1.1.0.tar.gz
cd ccf-qq-relay-1.1.0
sha256sum -c MANIFEST.sha256
```

先检查安装计划。路径和端口须替换为自己的值，无须填写授权 QQ：

```bash
./install.sh \
  --onebot-url ws://127.0.0.1:3001 \
  --napcat-config /path/to/onebot11_ACCOUNT.json \
  --napcat-port 3001 \
  --dry-run
```

检查通过后去掉 `--dry-run`，执行相同指令。安装器会创建专用虚拟环境、安装依赖、生成配置和 systemd 用户服务；不会修改 NapCat 配置，也不会自动执行 `sudo`。

| 参数 | 含义 |
|---|---|
| `--onebot-url <地址>` | 正向 WebSocket 地址，默认 `ws://127.0.0.1:3001` |
| `--napcat-config <路径>` | 只读自己的 NapCat OneBot 配置，从选定端口读取令牌 |
| `--napcat-port <端口>` | 选定的正向 WebSocket 端口；须与配置匹配 |
| `--prefix <专用目录>` | 默认 `~/.local/share/ccf-qq-relay` |
| `--enable` | 安装后立即启动并启用用户服务 |
| `--dry-run` | 只读检查；不写文件、不联网、不启动服务 |

安装器保留已有 `config.json` 和数据库，并拒绝覆盖不同内容的程序或服务文件。重复执行同一版本是安全的；升级时先停止服务并备份，再使用新安装目录，迁入自己的配置与数据库。迁移后须调整或移除旧的同名用户服务。旧版本的 `--admin-qq` 参数仍被接受以兼容安装脚本，但不产生任何权限限制。原目录升级时，须先停止服务并一致性备份数据库，再同步更新 `relay.py`、`ccfolia.py`、`onebot.py`、`commands.py`、`notifications.py`、`bootstrap.py` 及依赖文件；保留原 `config.json` 和完整数据库，随后重启。程序只新增数据表，不删除既有订阅、去重记录、防刷屏状态或待发提醒。原有 `allowed_user`、`allowed_users` 配置均不限制用户。

## 启动、检查与停用

默认安装目录为 `~/.local/share/ccf-qq-relay`。先核对配置，再启动：

```bash
cd ~/.local/share/ccf-qq-relay
.venv/bin/python bootstrap.py check --config config.json
systemctl --user enable --now ccf-qq-relay.service
systemctl --user status ccf-qq-relay.service --no-pager
journalctl --user -u ccf-qq-relay.service --since '10 minutes ago' --no-pager
```

配置检查不访问 CCF 或 OneBot，也不验证网络连通性。启动后，由任意 QQ 用户私聊登记账号并订阅房间，用 `.ccf提醒 测试 <房间网址>` 核对访问与提醒格式，再用一条新的公开 CCF 消息核对自动送达。

用户服务若需退出登录后和开机时持续运行，系统管理员须为运行账号启用 linger：`loginctl enable-linger <运行账号>`。安装器不自动执行此项。

```bash
systemctl --user restart ccf-qq-relay.service
systemctl --user disable --now ccf-qq-relay.service
```

停用本服务不会停止 OneBot 或骰子。卸载时先停用服务，再删除 `~/.config/systemd/user/ccf-qq-relay.service`，运行 `systemctl --user daemon-reload`，最后删除专用安装目录。删除数据库会清除绑定、订阅与待发提醒。

## 使用环境变量提供 OneBot 令牌

非 NapCat 服务可省略 `--napcat-config` 和 `--napcat-port`。在安装目录手动创建 `token.env`：

```text
CCF_ONEBOT_TOKEN=YOUR_ONEBOT_TOKEN
```

```bash
chmod 600 token.env
systemctl --user restart ccf-qq-relay.service
```

此文件只填写自己的 OneBot 令牌。CCFOLIA 账号密码通过私聊登记；无需写进配置。未设置访问令牌的 OneBot 可以不建 `token.env`。手动前台运行时须自行向进程提供环境变量；程序不会直接加载 `token.env`。

## 手动安装

在发行包目录执行：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp config.example.json config.json
```

在 `config.json` 中填写实际 `onebot_url` 即可，无需设置 `allowed_user` 或 `allowed_users`；所有 QQ 用户都可以使用指令。旧版配置中即使保留 `allowed_user` 或 `allowed_users`，程序也会忽略。再启动：

```bash
.venv/bin/python bootstrap.py check --config config.json
.venv/bin/python relay.py --config config.json
```

Windows 使用 `py -3` 创建虚拟环境，运行程序时将 `.venv/bin/python` 换为 `.venv\Scripts\python.exe`；复制文件与设置环境变量使用对应系统命令。手动方式不安装常驻管理服务。

## 配置

| 字段 | 含义 |
|---|---|
| `database` | SQLite 路径；相对路径基于配置文件所在目录，默认 `state/relay.sqlite3` |
| `onebot_url` | OneBot v11 正向 WebSocket 地址 |
| `onebot_token_env` | 令牌环境变量名，默认 `CCF_ONEBOT_TOKEN` |
| `allowed_user` / `allowed_users` | 兼容旧版的废弃字段，已忽略；不限制任何 QQ 用户 |
| `napcat_config` | 可选，自己的 NapCat OneBot 配置路径；优先从该文件读取令牌 |
| `napcat_ws_port` | 可选，从 NapCat 配置选取的正向 WebSocket 端口 |
| `poll_seconds` | 正常源消息轮询间隔，默认 3 秒 |
| `rescan_seconds` | 从订阅起点完整核查历史的间隔，默认 300 秒；房间及公开频道元数据每轮消息轮询都会刷新 |
| `send_interval` | QQ 提醒间隔，默认 1.2 秒 |

间隔必须是有限正数。轮询和补收会访问 Firebase，消息量、订阅时长及订阅账号数增加时，请求量也会增加。网站不提供本项目的兼容性承诺。

同一数据库路径只能运行一个服务实例；重复启动会直接退出。服务锁不能替代进程清理：升级时应确认没有其他配置指向另一份数据库、同时监听同一个 QQ。

## 凭据与备份

安装目录和状态目录应仅运行账号可访问，配置、令牌文件及数据库应保持私有权限。数据库包含已登记邮箱、CCF 登录令牌及刷新令牌，应按凭据保管；程序不保存明文密码。登录令牌可跨房间复用。QQ 平台、NapCat 或其他骰子程序可能记录收到的绑定指令。

备份数据库前先停止服务，或使用 SQLite 一致性备份。运行中的数据库不能只复制主文件而忽略 WAL。更换主机可迁移专用配置、数据库和 OneBot 令牌，随后检查路径和 OneBot 连接。

所有 QQ 用户均可发送命令；群内所有成员都能查询、增加或关闭该群已绑定房间的频道。请评估公开部署带来的访问量和管理风险。

对外分享使用原始发行包或重新运行 `package_release.py`。不要加入 `config.json`、`token.env`、状态数据库、NapCat 配置、日志或运行备份。
