## 尚未验证与已知边界

- 未主动新发 CCF 消息或向真实 QQ 发送测试提醒，未完成新源消息到 QQ 的主动全链路测试。安装者仍须核对自己的 OneBot 地址、令牌与授权 QQ，并在实际使用中核对新消息送达。
- 源站采用轮询：默认每轮完成后等待 3 秒，实际延迟另受请求、分页、QQ 队列及网络影响。每轮刷新频道元数据；默认每 300 秒从最早订阅起点完整扫描一次历史。
- 提醒按采集时的公开状态过滤。已进入待发队列的提醒只保留元数据；源消息之后删除、改为私信或频道之后改为私密时，队列中的既有提醒不会自动撤回。
- QQ 已接受消息但本地尚未确认时发生故障，重试可能重复。补收前已删除的源消息无法恢复。接口及账号权限变化可能要求更新程序或重新绑定。
- 邮箱密码以 QQ 私聊指令提供；虽然本服务不保存它们，QQ、OneBot 及其他骰子程序仍可能记录原始指令。

## 协议依据

CCFOLIA 1.37.6 官方前端应用在核验时使用 Firebase 项目 `ccfolia-160aa`。公开应用 API key 为网站自身的项目标识，不是安装者账号凭据。

- [CCFOLIA 官方网站](https://ccfolia.com/)
- [核验时的官方应用脚本](https://ccfolia.com/static/js/main.0f872b7d.js)：房间 `messageGroups` / `messageChannels`、消息 `channel` / `createdAt`、私信 `to` 与暗骰标记。
- [Firebase Auth REST 文档](https://firebase.google.com/docs/reference/rest/auth)：密码登录与刷新令牌。
- [Firestore StructuredQuery 文档](https://firebase.google.com/docs/firestore/reference/rest/v1/StructuredQuery)：消息排序、频道查询与分页。

## 自行复核

安装依赖后，在源码或解压后的发行目录执行：

```bash
.venv/bin/python -m unittest discover -s tests -p 'test_*.py' -v
```

测试会临时监听本机回环地址，不接入真实 QQ 或 CCF。可选源站只读检查会交互式询问房间网址、邮箱和密码，不保存账号信息，也不输出房间消息正文、昵称或令牌：

```bash
.venv/bin/python tools/check_source.py
```

源站检查工具与测试资料保留在发行目录中；自动安装器只把服务运行必需的文件复制到安装目录。
